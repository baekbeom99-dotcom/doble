# 한글·알파벳 도블 게임 설계서

- 작성일: 2026-11-09
- 상태: 섹션 1~3 확정, 섹션 4 제안(검토 필요)

## 0. 개요

### 목적
- **주 목적**: 아이들이 한글 자음, 한글 음절, 알파벳을 놀이로 익히기
- **부 목적**: 가족이 함께하는 파티 게임
- 도블 방식: 두 카드에 공통으로 있는 심볼이 정확히 1개이고, 그 심볼을 먼저 찾는 게임

### 기본 조건
| 항목 | 결정 |
|---|---|
| 플랫폼 | 웹앱(PWA), 태블릿 가로 화면, 터치 입력. 오프라인 동작 |
| 인원 | 1~4인, **한 기기를 함께 사용**(서버 없음) |
| 모드 | 혼자 하기, 경쟁, 협동, 팀 경쟁 |
| 기술 스택 | TypeScript + Vite + React, 테스트는 Vitest |
| 카드 생성 | 라운드마다 즉석 생성(고정된 수학적 덱을 쓰지 않음) |

### 심볼 세트
| 세트 | 내용 | 개수 |
|---|---|---|
| 한글 자음 | ㄱ~ㅎ 기본 14개, 쌍자음 포함 시 19개 | 14 / 19 |
| 초성 음절 | 초성 하나를 고르면 그 초성으로 시작하는 음절. 받침 없음: 가·갸·거·겨… / 받침 있음: 각·간·갈… | 받침 없음은 기본 모음 10개(ㅏㅑㅓㅕㅗㅛㅜㅠㅡㅣ)만 쓰고 이중모음(ㅐㅒㅔㅖㅘㅙㅚㅝㅞㅟㅢ)은 뺀다 → 10개, 카드당 최대 5개. 받침 있음은 자주 쓰는 음절만 골라 씀 |
| 알파벳 | 대문자 / 소문자 / 섞기 | 26 / 26 / 52 |
| 이미지 | 내장 이미지 세트 + 사용자가 올린 이미지 세트 | 세트마다 다름 |

- 한 세트에 필요한 최소 심볼 수는 `카드당 심볼 수 × 2 − 1`이다. 카드당 3개면 5개, 8개면 15개가 필요하다.
- 심볼이 부족하면 해당 난이도를 잠그고 "N개 더 필요해요"라고 알려준다.

## 1. 게임 규칙

### 1.1 공통 규칙
- 화면 가운데에 **중앙 카드** 1장, 각 플레이어 자리에 **자기 카드** 1장을 둔다.
- 내 카드와 중앙 카드에 같이 있는 심볼을 **내 카드에서** 터치한다.
- 라운드마다 중앙 카드와 모든 플레이어 카드를 새로 만든다.
  - 플레이어 카드와 중앙 카드의 공통 심볼은 정확히 1개다.
  - 플레이어마다 정답 심볼이 서로 다르다. 남의 정답을 보고 따라 할 수 없게 하기 위해서다.
  - 카드당 심볼 수가 인원보다 적으면 정답이 겹치는 것을 허용한다.
- **오답**: 틀리게 터치한 플레이어만 1.5초 동안 터치가 막힌다(마구 누르기 방지). 카드가 흔들리고 빨간 테두리가 깜빡인다.
- **플레이어별 난이도**: 사람마다 카드당 심볼 수를 3~8개로 따로 정한다. 중앙 카드의 심볼 수는 그중 가장 큰 값에 맞춘다.
- **중앙 카드 회전**: 턴마다 중앙 카드를 90°씩 돌린다(0 → 90 → 180 → 270°). 모든 참가자가 돌아가며 바로 보는 글자를 받게 하려는 것이다. 설정에서 180°씩 번갈아 돌리기나 안 돌림으로 바꿀 수 있다. 기본값은 90°이고, 혼자 하기는 마주 앉은 사람이 없으므로 안 돌림이 기본이다.
- **심볼 회전·크기 변화**: 켜고 끌 수 있다. 아이용은 끄는 것을 권장한다.
- **정답 읽어주기**: 정답을 맞히면 그 글자나 이미지 이름을 소리로 읽어준다. 브라우저 음성 기능(Web Speech API)을 쓰고, 설정에서 켜고 끈다.

### 1.2 혼자 하기 (1인)
세 가지 방식 중 하나를 고른다.

| 방식 | 규칙 |
|---|---|
| 서바이벌 타임어택 | 40초로 시작한다(설정에서 20·40·60초 중에 고른다, 2026-11-11). 맞히면 +3초, 틀리면 −2초이고, 시간이 0이 되면 끝난다. |
| 스테이지 도전 | 스테이지마다 목표가 있다(예: 20초 안에 10개 맞히기). 클리어하면 ★1~3개를 받고, 스테이지가 오를수록 심볼 수가 늘어난다. |
| 몬스터 사냥 | 협동 모드를 혼자 하는 버전. 불을 맞으면 풀어 줄 친구가 없으므로 5초 뒤 저절로 풀리고 하트가 1개 준다. |

세 방식 모두에 붙는 요소:
- **반응 속도 판정**: 빨리 맞힐수록 Perfect, Great, Good 순으로 점수를 더 준다.
- **콤보와 피버 타임**: 5연속으로 맞히면 5초 동안 점수 2배가 되고 화면 효과가 나온다.
- **아이템**: 맞히면 일정 확률로 얻는다.
  - 💡 힌트: 내 정답이 반짝인다.
  - ⏸️ 시간 정지: 3초 동안 시간이 멈춘다.
  - ✨ 점수 2배
- **기록과 수집**: 세트별 최고 기록과 별 개수를 기기에 저장한다. 조건을 달성하면 스티커나 배지를 준다(예: "ㄱ 마스터", "알파벳 100개 찾기").
- **나와의 대결(고스트)**: 서바이벌에서 내 최고 기록을 진행 막대로 함께 보여준다.

### 1.3 경쟁 (2~4인)
대결 방식은 셋 중 하나를 고른다.

| 방식 | 맞히면 | 승리 조건 |
|---|---|---|
| 점수제 | +1점 | N라운드가 끝났을 때 점수가 가장 높은 사람, 또는 목표 점수에 먼저 도달한 사람 |
| 폭탄 돌리기 | 내 카드 1장을 상대에게 넘긴다. 누구에게 넘길지는 직접 고르거나 무작위로 정한다 | 들고 있는 카드를 먼저 다 없앤 사람이 이긴다. 카드가 가장 많이 남은 사람이 진다 |

세 방식 모두에 덧붙는 요소:
- **콤보**: 3연속으로 맞히면 그다음부터 2점(또는 카드 2장)을 받는다. 남이 먼저 맞히거나 내가 틀리면 콤보가 끊긴다.
- **막판 3배**: 마지막 라운드는 점수가 3배다. 폭탄 돌리기에서는 카드를 3장 넘긴다.
- **폭탄 돌리기 표시** (2026-11-11): 설정 화면과 게임 정보 칸에 규칙을 보여준다. 이름 옆 카드 수 뒤에 작은 카드 그림(최대 7장, 넘으면 +)을 붙이고, 카드를 넘길 때 카드가 날아가는 효과를 보여준다.
- **아이템**: 맞히면 20% 확률로 얻고, 한 번에 1개만 가질 수 있다.
  - ❄️ 얼리기: 상대 전원이 2초 동안 멈춘다.
  - 🌀 뒤섞기: 상대 카드의 심볼이 빙글빙글 돈다.
  - 💡 힌트: 이번 라운드 내 정답이 반짝인다.
  - 🛡️ 방패: 상대의 공격 아이템을 1번 막는다.

### 1.4 팀 경쟁 (3~4인)
- 규칙은 경쟁과 같고, 점수나 카드를 팀별로 합친다.
- 4인은 2:2, 3인은 2:1로 나눈다. 3인일 때 1명인 쪽은 난이도를 낮춰 균형을 맞춘다.
- 아이템의 "상대"는 상대 팀이다.

### 1.5 협동 (1~4인): 악당 거북이 물리치기 + 학습 미션
- **기본 구조**: 악당 거북이 체력 바, 팀 공용 하트 3개, 불 공격까지 남은 시간을 보여주는 막대가 있다.
- **공격**
  - 정답 1개마다 거북이에게 피해 1을 준다.
  - 한 라운드 안에서 모두가 맞히면 **합체 공격**이 나가 맞힌 사람 수만큼 피해를 더 준다.
- **오답 벌칙**: 틀리면 불 공격까지 남은 시간이 1.5초 줄어든다 (불 공격 중에는 줄지 않는다).
- **불 공격** (예전의 원소 순서·공동 목표 방어 챌린지를 대신한다, 2026-11-10)
  - 악당 거북이는 이리저리 고개를 돌리다가 8~12초마다(단계마다 5%씩 빨라지고 최소 5초) 한 사람을 골라 불(드래곤 브레스)을 뿜는다.
  - 불을 맞은 사람은 그동안 누를 수 없다.
  - **다른 친구들이 합쳐서 2번 맞히면** 불이 꺼진다 (하트 그대로).
  - 5초 안에 못 끄면 저절로 풀리고 하트가 1개 준다.
  - 불 맞은 사람을 빼고 모두 맞히면 그 라운드의 합체 공격이 나간다.
  - 불 공격 중에 거북이를 물리치면 불도 꺼진다.
- **상황 문구**: 일이 생길 때마다 정보 칸 옆에 한 문장으로 알려 준다. 예: "악당 거북이가 민지에게 불을 뿜었어요! 친구들이 2번 맞히면 구할 수 있어요", "민지를 구했어요!", "불을 못 껐어요. 하트가 하나 줄었어요", "악당 거북이를 물리쳤어요! 2단계 거북이가 나타났어요", "미션 성공! 하트가 하나 늘었어요". 정보 칸에는 불 공격 중 "민지 구하기 1/2 · 4초"를 보여 준다.
- **학습 미션**
  - 거북이마다 미션이 1개씩 붙는다(예: "모음 ㅗ가 들어간 글자를 정답으로 3번 찾기").
  - 성공하면 보상으로 하트 회복, 피해 보너스, 필살기 중 하나를 받는다.
  - 카드를 만들 때 미션 조건에 맞는 심볼이 정답으로 더 자주 나오도록 조절한다.
- **스테이지**: 거북이를 잡을 때마다 공격이 빨라지고 심볼 수가 늘어난다 (세트가 허락하는 만큼). 하트가 0이 되면 게임 오버이고, 도달한 스테이지가 기록이 된다.
- **2026-11-11 바뀐 점**
  - 미션에 성공하면 거북이에게 큰 피해를 준다.
  - 불 게이지는 정보 칸 밖에 크게 그린다. 2~4인은 양쪽에 하나씩, 1인은 화면을 가로지르는 긴 막대다.
  - 1인 몬스터 사냥: 찾기 미션이 없다. 정답을 맞힐 때마다 불 공격이 늦춰진다. 불 공격 중 문구는 "방어하는 중"이다.
  - 1인 몬스터 사냥: 거북이를 물리치면 3초 동안 연출(번쩍임, 불꽃, 문구, 다음 거북이 등장)이 나오고 그동안 시간이 흐르지 않는다.
  - 1인 몬스터 사냥: 3단계부터 거북이가 좌우로 자리를 옮기고, 단계가 높을수록 더 자주 옮긴다.
  - 1인 몬스터 사냥: 5번 맞힐 때마다 하트가 1개 회복된다(최대 5개).
  - 여럿이 할 때도 한 사람이 맞힐 때마다 불 공격이 0.7초 늦춰진다(1인은 1.5초). 이번 공격 간격을 넘지는 않는다.
  - 미션 문구를 크게 보여준다. 불을 뿜을 때 화면이 깜빡이지 않게 화면 전체 그림자를 빼고 일렁임을 약하게 했다.

## 2. 코드 구조

### 2.1 원칙
- 게임 엔진은 React 없이 **순수 TypeScript**로 짠다.
- 화면(UI)은 엔진의 상태를 그리기만 하고, 사용자 입력은 행동(Action)으로 바꿔 엔진에 넘긴다.
- 시간도 `TICK(dt)` 행동으로만 흐르게 한다. 그래서 테스트에서 시간 경과를 바로 흉내 낼 수 있다.
- 난수는 시드를 고정할 수 있게 해서 결과를 재현할 수 있게 한다.

### 2.3 주요 인터페이스
- **Symbol**
  ```ts
  {
    id: string;
    display: { kind: 'text'; value: string } | { kind: 'image'; src: string };
    speech: string;                 // 읽어줄 말
    tags: { initial?: string; vowel?: string; batchim?: boolean; [k: string]: unknown };
  }
  ```
  - 미션 조건은 `tags`로 판단한다.
- **SymbolSet**: `{ id, name, loadSymbols(): Promise<Symbol[]> }`. 글자 세트는 바로 결과를 돌려주고, 이미지 세트는 파일을 읽어서 돌려준다.
- **카드 생성**
  ```ts
  generateRound({ pool, centerSize, playerSizes[], preferAnswer?, rng })
    → { center, playerCards[], answers[] }
  ```
  - `preferAnswer`: 미션 조건에 맞는 심볼이 정답으로 더 자주 나오게 하는 조건이다.
- **Mode**: `{ init, onCorrect, onWrong, onTick, isOver, result }`. 승패와 진행 방식을 정한다.
- **Modifier**: 같은 이벤트에 끼어들어 점수나 효과를 바꾼다(예: 콤보가 +1점을 +2점으로 바꿈). 설정에서 켠 것만 적용한다.
- **배치**
  ```ts
  layoutSymbols({ region, exclusions, count, sizeRange, minGap, inset, targetFill, rng })
    → { x, y, size, rotation }[]
  ```
  - `region`: 타원과 화면 사각형이 겹치는 부분. 원은 가로·세로 반지름이 같은 타원으로 처리한다.
  - `exclusions`: 콤보·아이템 칸처럼 영역 안에 있지만 글자를 놓으면 안 되는 사각형 목록.

### 2.4 데이터 흐름
```
터치(pointerdown)       → TAP(playerId, symbolId)
requestAnimationFrame  → TICK(dt)
아이템 버튼             → USE_ITEM(playerId)
         ↓
  reducer: Mode → Modifiers 순서로 적용
         ↓
  새 GameState → React가 다시 그림
  이벤트 목록   → 효과음 · 음성 · 애니메이션
```
- 여러 손가락이 동시에 닿아도 `pointerdown`으로 각각 받는다. 먼저 도착한 행동이 이긴다.
- 각 자리 영역은 자기 터치만 처리하고, 남의 카드를 터치하면 무시한다.

### 2.5 이미지 세트
- **내장 세트**
  - `public/symbol-sets/<setId>/manifest.json`에 이미지 파일을 함께 둔다.
  - manifest 예시: `{ id, name, symbols: [{ file, speech, tags }] }`
  - 세트를 추가하려면 폴더를 만들고 `registry`에 한 줄을 넣는다.
- **사용자 세트** ("내 세트 만들기" 화면)
  1. 사진첩이나 카메라에서 여러 장을 선택한다(`<input type="file" accept="image/*" multiple>`).
  2. 가운데를 기준으로 정사각형으로 자르고, 256px WebP로 줄인다.
  3. 이미지마다 이름을 붙인다(선택). 정답일 때 이 이름을 읽어준다.
  4. IndexedDB에 저장하고, 수정과 삭제를 할 수 있게 한다.
- 게임 시작 전에 모든 이미지를 미리 불러와서, 라운드 중에 그림이 늦게 뜨지 않게 한다.
- 엔진은 심볼 `id`만 다룬다. 글자인지 이미지인지는 Card 컴포넌트만 구분한다.

### 2.6 테스트
- 엔진은 Vitest로 단위 테스트한다. 대상은 카드 생성, 배치, 각 모드, 각 덧붙는 요소, 협동 하위 시스템이다.
- 카드 생성은 시드를 바꿔 가며 1000번 이상 돌려서 다음을 확인한다.
  - 플레이어 카드와 중앙 카드의 공통 심볼이 정확히 1개인지
  - 플레이어끼리 정답이 다른지
- 배치는 다음을 확인한다.
  - 모든 글자 상자가 영역 경계에서 8px 이상 안쪽에 있는지
  - 글자끼리 간격이 8px 이상인지
  - 최소 터치 크기(44px)를 지키는지
- 화면은 실제 터치 흐름 몇 가지만 확인한다.

## 3. 화면 구성과 디자인

### 3.1 화면 흐름
```
타이틀(모드 카드 4장) → 게임 설정(인원·이름·자리 색 → 세트 → 난이도) → 게임 → 결과 → 다시 하기 / 홈
홈 → 내 세트 만들기
홈 → 수집함 (스티커, 배지, 기록)
```

### 3.2 자리 배치 (태블릿 가로, W×H 기준)
| 인원 | 플레이어 영역 | 중앙 카드 | 게임 정보 |
|---|---|---|---|
| 1인 (서바이벌·스테이지) | 아래 가운데 **정반원**(반지름 0.42×0.8×min(W,H)에서 정보 칸·해와 닿지 않을 때까지 줄임) 1자리. 거북이 뒷모습(3.6) | 해·달: 반지름 0.19×0.8×min(W,H). 바다 왼쪽 중간 → 위 가운데 → 오른쪽 중간으로 반타원을 따라 정답마다 움직인다 (3.6) | 왼쪽 아래 모서리 |
| 1인 (몬스터 사냥) | 아래 가운데 반타원 | 위 가운데 | 왼쪽 위 모서리 |
| 2인 | 원의 중심을 위·아래 가장자리에 두고, 각자 **자기 기준 오른쪽** 모서리 쪽으로 옮긴다. 그래서 아래쪽 사람은 오른쪽 아래, 위쪽 사람은 왼쪽 위에 놓여 대각선으로 엇갈린다. 반원만 보이고, 위쪽 자리는 180° 회전한다 | 화면 정가운데 | 공용 정보(라운드, 진행 막대)는 비어 있는 대각선 모서리(왼쪽 아래, 오른쪽 위)에 각자 방향으로 1칸씩 둔다. 점수는 3.2.1처럼 이름 끝에 붙인다 |
| 3~4인 | **타원**의 중심을 모서리에 두고 화면 중앙 쪽으로 각 반지름의 1/3만큼 옮긴다. 긴 변 방향(가로) 반지름은 길게, 짧은 변 방향(세로) 반지름은 짧게 해서 다른 영역과 겹쳐 보이지 않게 한다. 아래쪽 자리는 정방향, 위쪽 자리는 180° 회전한다. 3인은 모서리 3곳을 쓴다 | 화면 정가운데 | 공용 정보는 가운데 줄의 왼쪽(아래쪽 사람 방향)과 오른쪽(위쪽 사람 방향)에 같은 내용으로 1칸씩 둔다. 점수는 3.2.1처럼 이름 끝에 붙인다 |

#### 3.2.1 이름과 점수 (점수 배지는 없앴다, 2026-11-10)
- 이름은 자기 영역 테두리 바깥을 따라 곡선으로 놓는다. 위치는 그 사람 기준 **왼쪽 테두리**(왼쪽 수평에서 30° 위)에서 시작하고, 화면 밖이거나 정보 칸·나가기 버튼에 걸리면 위쪽으로 옮긴다. 모서리 자리처럼 왼쪽이 화면 밖이면 보이는 가장 왼쪽에 놓는다.
- 글자 위쪽이 늘 영역 바깥을 향하게 그려서 위쪽 자리는 뒤집혀 보이고, 각자 자기 자리에서 읽힌다.
- 점수는 이름 끝에 다른 색(주황 #d9583b) 글자로 붙인다. 팀 대결은 이름 앞에 A/B를 붙인다. 협동은 점수를 붙이지 않는다.
- 콤보·아이템·대상 버튼은 예전 배지 자리에서 영역 안쪽으로 떨어진 칸에 놓고, 그 칸에는 글자를 놓지 않는다.
- 설정 화면의 이름 입력칸은 이름 길이에 맞춰 늘고 준다 (최대 10자).

- 크기 계산 순서
  1. 게임 정보 칸의 크기를 먼저 정한다.
  2. 남은 공간에서 플레이어 영역의 크기를 정한다. 모든 영역과 중앙 카드는 2026-11-10에 20% 줄였다(중앙 카드 0.22→0.176, 1인 0.26→0.208, 협동 0.17→0.136 ×min(W,H)). 영역끼리 겹치지 않고, 중앙 카드와는 그 반지름의 20% 이상 띄운다. 협동은 악당 거북이가 들어가도록 중앙 카드를 0.17×min(W,H)로 줄이고, 영역을 카드 반지름의 2.2배 밖에 둔다.
  3. 기기 화면 크기에 맞춰 자동으로 계산한다(`engine/seats.ts`).
- **나가기 버튼**: 게임 중 언제든 누를 수 있다. 자리 영역이 닿지 않는 곳에 둔다(1인 오른쪽 위, 2인 왼쪽 가운데, 3~4인 위 가운데). 누르면 확인 창("게임을 그만할까요?")이 뜨고 그동안 게임 시간이 멈춘다. 그만두면 기록 없이 처음 화면으로 간다.
- 게임 정보 칸은 작게 둔다(시안 기준 높이 약 26~34px). 협동·혼자 하기의 큰 정보 칸은 0.2W × 0.15H이고 줄 간격을 좁힌다. 협동 모드에서는 공용 정보 칸에 거북이 체력, 팀 하트, 불 공격 막대(또는 구하기 진행), 미션을 넣는다.

### 3.3 글자 배치 규칙
- 각 글자 상자는 보이는 영역의 경계선에서 **안쪽으로 8px 이상** 떨어진다. 화면에 잘린 가장자리도 경계선으로 본다.
- 글자끼리 간격은 **최소 8px**이다.
- 보이는 영역 넓이의 **약 70%**를 글자가 차지하는 것을 목표로 한다.
- 글자 크기는 기준 크기의 0.6~1.4배 사이에서 무작위로 정해 다양하게 만든다.
- 배치 알고리즘
  1. 크기 비율을 정하고, 목표 70%에 맞춰 기준 크기를 계산한다.
  2. 큰 글자부터 영역 안에서 무작위로 자리를 찾는다(경계 여백과 간격 조건 확인).
  3. 자리를 찾지 못하면 기준 크기를 5% 줄이고 다시 시도한다.
  4. 최소 크기(터치 44px)에 도달하면 70%를 다 채우지 못해도 멈춘다. 여백과 간격 조건이 70% 목표보다 우선한다.
- 같은 시드를 넣으면 같은 배치가 나온다.

### 3.4 디자인: 페이퍼컷 (2026-11-10, 네오브루탈리즘을 대신한다)
- **바탕**: 따뜻한 크림 종이(#efe4d0)에 화면 전체로 옅은 종이 결을 깐다.
- **겹친 종이**: 검은 테두리를 쓰지 않는다. 같은 색 종이를 12%, 25% 어둡게 한 두 겹 고리로 두르고, 그림자는 아래로 부드럽게 떨어진다. 영역, 중앙 카드, 버튼, 설정 칸, 정보 칸, 창 모두 같은 방식이다.
- **자리 색** (차분한 파스텔): 핑크 #F4AEBD, 하늘 #A3D2E6, 노랑 #F4D97F, 연두 #C2DF97, 보라 #C3B6F2. 중앙 카드는 크림 종이(#FFFAF0)다.
- **배경 무늬**: 혼자 하기 외에는 크림 바탕에 물결·도트·지그재그·격자 무늬를 음각으로 새긴다. 정답이 나올 때마다 다음 무늬로 부드럽게 바뀌고, 무늬는 천천히 흐른다.
- **글자**: 한글 Jua, 알파벳 Fredoka. 글자색은 짙은 갈색(#3a2e2a)이고, 4px 흰 테두리(오프셋)와 부드러운 그림자를 둔다.
- **정답 피드백**: 정답 글자가 한 번 튀어 오르고 노란 종이가 씌워지며, 화면 가장자리가 맞힌 사람의 영역 색으로 두 번 반짝인다.
- **설정 화면**: 초성 고르기는 토글 버튼, 켜고 끄는 항목은 스위치로 보여준다. 스크롤 없이 한 화면에 담는다: 위 막대(처음으로·제목·시작), 왼쪽 칸(방식·인원·플레이어), 오른쪽 칸(글자 세트, 대결 방식 칸 안에 라운드 수·폭탄 옵션·덧붙는 요소, 그 밖의 설정 칸 안에 회전·심볼 회전·읽어주기).
- **중앙 카드 바닥 띠**: 카드 아래쪽 15%를 곧은 수평선으로 잘라 갈색 종이로 칠하고, 카드와 함께 회전해 글자의 바닥을 알려 준다. 띠에는 글자를 놓지 않는다. 회전은 90°가 기본이고, 혼자 하기는 회전하지 않는 것이 기본이다.
- **나가기**: 게임 중 언제든 누를 수 있는 종이 버튼 (3.2).

### 3.6 장면과 캐릭터 (2026-11-10)
- **타이틀 화면**: 민트색 하늘, 두 겹 종이 구름, 주황 종이 고리 여덟 장을 겹친 해, 초록 언덕 다섯 겹, 언덕 위의 하얀 종이 거북이. 해 안에 제목 **"Turtle Dobble"** (두 줄 같은 크기). 아래 언덕 위에 세로로 긴 모드 카드 4장(혼자 하기, 같이 하기, 팀 대결, 협동: 그림 칸 + 이름 + 한 줄 설명)과 왼쪽 위 수집함 버튼.
- **혼자 하기 (하늘과 바다)**
  - 위쪽 절반은 하늘, 아래쪽 절반은 겹친 종이 물결 바다.
  - 중앙 카드는 해(노란 종이 고리 + 햇살 조각)다. 정답마다 바다 왼쪽 중간에서 위 가운데를 지나 오른쪽 중간으로 조금씩 움직인다(12번에 끝). 그다음은 달이 왼쪽에서 떠서 같은 길을 가고, 다시 해가 된다.
  - 하늘·바다 색은 해·달 위치에 맞춰 바뀐다 (해 뜰 녘 → 한낮 → 노을, 초저녁 → 한밤 → 새벽 전).
  - 낮에는 구름과 새, 밤에는 별이 천천히 나타났다가 흐르며 사라진다.
  - 내 영역은 헤엄치는 거북이의 뒷모습이다: 초록 등껍질에 엇갈린 격자 무늬, 양옆 뒷다리, 등껍질 위로 엄지손가락처럼 굵고 끝이 둥근 한 가지 색 베이지 뒤통수(얼굴은 보이지 않음). 뒤통수만 천천히 갸웃거리고, 해·달이 어디 있어도 닿지 않는 높이로 둔다. 맞히면 머리가 들썩이고 뒤통수 양쪽에 분홍 사선 3개씩 홍조가 1.2초 동안 생긴다.
- **협동 (악당 거북이)**
  - 중앙 카드가 악당 거북이 등껍질 가운데다. 가시가 두 겹 돋친 짙은 등껍질(단계마다 색이 바뀜), 주황·빨강 피부와 짙은 반점, 굵은 다리와 발톱, 가시 꼬리.
  - 머리는 크고 앞으로 갈수록 좁아지며, 눈썹 없이 입 쪽으로 모이는 대각선 아몬드꼴의 매서운 눈, 가운데가 갈라지지 않은 한 덩어리 입, 앞쪽 부리 끝 하나, 머리 위 불꽃 볏을 가진다.
  - 평소에는 이리저리 고개를 돌리고, 불 공격이 시작되면 맞는 사람 쪽으로 고개를 다 돌린 뒤(0.7초) 불을 뿜는다. 맞으면 눈이 ×가 되며 흔들린다.
  - 불은 드래곤 브레스처럼 입에서 부채꼴로 넓게(끝 폭 카드 반지름의 2.4배) 퍼지는 네 겹 불길(진홍·주황·노랑·흰빛)이고, 물결치는 테두리가 숨 쉬듯 일렁이며 불티가 튄다. 맞은 영역은 주황빛으로 일렁이고 글자가 흐려진다.

### 3.5 터치 처리
- 멀티 터치를 지원한다. 각 자리 영역은 자기 터치만 받는다.
- 브라우저 기본 동작(확대, 스크롤, 길게 눌러 메뉴 띄우기)을 막는다(`touch-action: none` 등).
- 화면을 가로로 고정한다.
- 터치하는 심볼은 최소 44px로 한다.

### 2026-11-11 화면 바뀐 점
- **설정 화면**: 상자마다 왼쪽 위에 아이콘 이름표를 달고 줄 사이를 가는 선으로 나눈다. 고르기 버튼은 금색 알약, 방식 버튼은 아이콘 타일이다. 혼자 하기는 네 상자의 높이를 맞추고 버튼을 세로로 늘린다. 4명이나 폭탄 돌리기처럼 고를 것이 많으면 촘촘하게 그린다.
- **기기 맞춤**: 설정 화면은 1024×768 기준으로 그리고, 기기 화면에 맞게 통째로 줄이거나 키운다(안쪽 배치는 그대로). 작은 기기에서도 상자가 화면 밖으로 나가지 않는다.
- **기본값**: 모든 모드에서 자음이 기본이다. 글자 수(예전 이름 심볼 수)는 고를 수 있는 범위의 가운데 값이 기본이다. "심볼이 부족해서" 안내는 없앴다.
- **전체 화면 버튼**: 아이콘만 있는 버튼을 첫 화면, 설정, 게임(나가기 왼쪽), 결과, 수집함에 둔다. 지원하지 않는 기기에서는 숨긴다.
- **사용 방법**: 첫 화면의 사용 방법 버튼을 누르면 놀이 방법과 모드별 설명이 담긴 안내 창이 열린다.
- **혼자 하기 정보 칸**: "아이템" 이름표와 아이템 칸을 두고, 얻은 아이템은 그 칸 안의 버튼으로 쓴다.

## 4. 1차 출시 범위와 개발 순서 (제안, 검토 필요)

기능이 많아서 단계별로 나눠 만든다. 각 단계는 끝나면 바로 플레이할 수 있는 상태가 된다.

| 단계 | 내용 |
|---|---|
| 1. 기반 | 프로젝트 세팅(Vite, React, TS, Vitest, PWA), 심볼 세트(자음, 초성 음절, 알파벳), 시드 난수, 카드 생성, 배치, 자리 계산 |
| 2. 핵심 플레이 | 게임 화면(1~4인 배치), 중앙 카드 회전, 터치·오답 잠금, 혼자 하기(서바이벌), 경쟁(점수제), 정답 읽어주기, 네오브루탈리즘 테마 (2026-11-10 페이퍼컷으로 바뀜) |
| 3. 경쟁 확장 | 폭탄 돌리기, 콤보, 막판 3배, 아이템, 팀 경쟁, 플레이어별 난이도 (탑 쌓기는 2026-11-11에 삭제) |
| 4. 협동 | 악당 거북이, 불 공격과 구출 (원소·공동 목표 방어는 2026-11-10에 불 공격으로 바뀜), 학습 미션, 스테이지 |
| 5. 혼자 하기 확장 | 스테이지 도전, 반응 속도 판정, 피버, 기록·별·배지, 고스트, 수집함 |
| 6. 이미지 (보류, 2026-11-10) | 내장 이미지 세트 로더, 내 세트 만들기(업로드, 자르기, IndexedDB). 추후 개발로 미룸. 엔진은 심볼 id만 다루고 Glyph가 image 심볼 표시를 이미 지원하므로, 세트 로더·업로드 화면만 추가하면 된다 |
